# Shelf Seasons: спецификация продукта

Статус: утверждённая спецификация; Stage 0–6 реализован; зашифрованный ежедневный бэкап базы подготовлен в 0.16.0

Бренд: **Shelf Seasons**

Основные языки первого релиза: English (`en`) и Русский (`ru`)

## 1. Назначение

Shelf Seasons — персональный визуальный дневник чтения. Приложение помогает хранить желаемые, текущие и прочитанные книги, отмечать ежедневное чтение, отслеживать циклы и серии, поддерживать непрерывную привычку и пересматривать месяц или год как историю из книжных обложек.

Приложение не является магазином, читалкой электронных книг, социальной сетью или сервисом рекомендаций в первом релизе.

## 2. Позиционирование

Ключевая идея: **не просто считать книги, а сохранять читательскую жизнь во времени**.

Основное отличие продукта:

- календарь с реальными обложками прочитанных в каждый день книг;
- быстрый ежедневный check-in без обязательного ввода страниц и минут;
- аккуратное ведение книжных серий;
- визуальные итоги месяца и года;
- спокойный интерфейс без чувства вины и давления;
- полноценная веб-версия и синхронизация между устройствами.

## 3. Неприкосновенные правила

1. **Shelf Seasons — единый бренд.** Название не переводится, не транслитерируется и не заменяется в зависимости от языка.
2. **Мультиязычие существует с первого этапа.** В компонентах запрещены необёрнутые пользовательские строки.
3. **Открытие приложения не считается чтением.** День учитывается только при сохранённой отметке чтения.
4. **Быстрая отметка допустима.** Пользователь может подтвердить чтение без страниц, процентов и минут.
5. **Пустая запись недопустима.** Отметка должна содержать положительный прогресс, положительное время или явный `check_in_only`.
6. **Серия дней вычисляется из записей.** Текущая и максимальная серии не редактируются вручную и не являются отдельным источником истины.
7. **Локальная дата пользователя важнее UTC-даты сервера.** Календарь и серия определяются в сохранённом IANA-часовом поясе профиля.
8. **Перечитывание — отдельный reading run.** Одна книга может иметь несколько завершённых циклов чтения.
9. **Разные издания не склеиваются автоматически.** ISBN, язык, обложка, формат и число страниц могут отличаться.
10. **Собственная обложка относится только к библиотеке загрузившего пользователя.** Она не изменяет данные других пользователей.
11. **Никаких паролей приложения.** Первый релиз использует Google OAuth через Supabase Auth.
12. **Все пользовательские таблицы защищены RLS.** Проверки только в интерфейсе недостаточно.
13. **Production не используется для экспериментов.** Разработка и проверка миграций выполняются в отдельной среде.
14. **Данные можно экспортировать и удалить.** Эти функции обязательны до публичного релиза.
15. **Запрещено объявлять этап завершённым без preflight-проверок.**

## 4. Целевая аудитория

Основной пользователь:

- читает бумажные, электронные и/или аудиокниги;
- хочет видеть красивую личную библиотеку;
- любит подводить итоги месяца и года;
- может читать несколько книг одновременно;
- хочет быстро отмечаться без сложного учёта;
- ценит приватность больше социальных механик.

## 5. Платформы

Первый релиз:

- адаптивное веб-приложение;
- installable PWA;
- поддержка актуальных Chrome, Edge, Safari и Firefox;
- мобильный интерфейс от 320 px;
- desktop-интерфейс без растянутых мобильных карточек.

Не входят в первый релиз:

- нативные iOS/Android-приложения;
- загрузка и чтение EPUB/PDF;
- офлайн-редактирование с последующей сложной синхронизацией.

PWA shell может кэшироваться, но пользовательские данные требуют соединения. При отсутствии сети интерфейс должен явно сообщать, что изменения не сохранены.

## 6. Аутентификация и onboarding

### 6.1 Вход

- единственная кнопка MVP: `Continue with Google` / `Продолжить с Google`;
- Supabase Auth с серверной cookie-сессией;
- пользователь после входа возвращается на безопасный внутренний URL;
- сессия сохраняется между обычными закрытиями браузера;
- ошибки OAuth показываются понятным текстом и не раскрывают технические секреты.

Apple OAuth рассматривается после подтверждения спроса и не блокирует первый релиз.

### 6.2 Первый запуск

Onboarding состоит максимум из трёх коротких шагов:

1. язык и автоматически определённый часовой пояс;
2. годовая цель по количеству завершённых чтений;
3. предложение добавить первую книгу или открыть демонстрационный пример.

Onboarding можно пропустить, кроме подтверждения языка и часового пояса.

## 7. Личная библиотека

### 7.1 Статусы

- `want_to_read` — хочу прочитать;
- `reading` — читаю сейчас;
- `paused` — отложено;
- `read` — прочитано хотя бы один раз;
- `dnf` — не дочитано;
- `archived` — скрыто из обычной библиотеки без удаления истории.

Статус `read` не удаляет возможность начать перечитывание. Во время активного перечитывания книга показывается как `reading`, сохраняя предыдущую историю.

### 7.2 Отображение

- плитка обложек с отношением сторон `2:3`;
- переключение между grid и compact list;
- фильтр по статусу, формату, языку, оценке, серии и году завершения;
- сортировка по последнему действию, названию, автору, дате добавления и дате завершения;
- строка поиска по собственной библиотеке;
- пагинация или cursor-based загрузка, без получения всей библиотеки одним запросом.

### 7.3 Форматы

- paper;
- ebook;
- audiobook;
- other.

Формат относится к конкретной записи пользовательской библиотеки и может быть изменён.

### 7.4 Сезонные полки

- пользователь может необязательно связать книгу с весной, летом, осенью или зимой;
- первой всегда показывается полка текущего времени года, затем остальные по календарному кругу;
- общий фон приложения передаёт настроение текущего сезона, но декоративные элементы остаются частью страницы и не перекрывают контент;
- закрытая полка выглядит как физическая деревянная полка: книги стоят вертикально корешками вперёд, рядом размещён сезонный декор;
- нажатие на любую область полки открывает плитку всех её книг с обложками и доступом к редактированию;
- сезонная привязка не меняет статус книги и не влияет на историю чтения.

## 8. Добавление книги

### 8.1 Поиск

Основной источник метаданных: Google Books API.

Поддерживается поиск по:

- названию;
- автору;
- ISBN-10/ISBN-13;
- комбинации названия и автора.

Результат показывает обложку, название, автора, язык, год и ISBN, чтобы пользователь мог выбрать нужное издание.

### 8.2 Резервные пути

1. Если подходящего результата нет — ручное добавление.
2. Если у результата нет обложки — попытка показать обложку Open Library по ISBN в рамках разрешённого использования.
3. Если обложки всё равно нет — локальный нейтральный placeholder.
4. Пользователь всегда может загрузить собственную обложку.

### 8.3 Редактирование

После импорта можно изменить личную копию следующих полей:

- title;
- subtitle;
- authors;
- language;
- page count или duration;
- publication date;
- format;
- cover override.

Изменение не должно исправлять глобальные данные других пользователей.

### 8.4 Дубли

- совпадение `external_source + external_id` у одного пользователя вызывает предложение открыть существующую запись;
- совпадение ISBN вызывает предупреждение, но не запрещает добавить другое издание;
- ручные дубли разрешены только после явного подтверждения.

## 9. Reading runs

Reading run — отдельная попытка прочитать книгу от начала до завершения, паузы или DNF.

Поля поведения:

- дата начала;
- необязательная дата окончания;
- статус `reading`, `paused`, `completed` или `dnf`;
- признак reread;
- способ отслеживания: pages, percent или minutes;
- текущая позиция;
- оценка после завершения;
- короткое впечатление;
- номинации для итогов.

У одной книги одновременно может быть не более одного активного reading run.

Допустимые переходы:

- `reading → paused`;
- `paused → reading`;
- `reading|paused → completed`;
- `reading|paused → dnf`;
- `completed|dnf → new reading run`, но не возврат старой записи в активное состояние.

## 10. Ежедневные отметки

### 10.1 Быстрый check-in

На главной странице у текущей книги доступна кнопка:

- EN: `Log today's reading`;
- RU: `Отметить чтение сегодня`.

Она создаёт `check_in_only` для выбранной книги и локальной даты пользователя. Повторное нажатие не создаёт незаметный дубль: приложение открывает существующую запись дня или предлагает добавить ещё одну сессию.

### 10.2 Подробная запись

Опциональные данные:

- start/end page;
- pages read;
- resulting percentage;
- minutes read;
- короткая заметка без rich text в MVP.

Пользователь может читать несколько книг в один день и создать несколько сессий.

### 10.3 Ограничения

- будущая локальная дата запрещена;
- отрицательные значения запрещены;
- процент находится в диапазоне 0–100;
- end page не меньше start page;
- одна сессия не может ссылаться на чужую книгу или reading run;
- backdate разрешён и немедленно пересчитывает календарь и streak.

## 11. Календарь

### 11.1 Режимы

- week;
- month;
- year mosaic.

### 11.2 Ячейка дня

- одна книга: одна обложка;
- две книги: разделённая или наложенная композиция;
- более двух: до двух обложек и индикатор `+N`;
- check-in без прогресса визуально равноправен другой подтверждённой сессии;
- нажатие открывает bottom sheet/modal со всеми сессиями дня.

Пустой день не изображается как ошибка или наказание.

## 12. Reading streak

День считается читающим, если существует хотя бы одна валидная сессия с:

- `check_in_only = true`; или
- `minutes_read > 0`; или
- `pages_read > 0`; или
- положительным изменением позиции/процента.

Показываются:

- current streak with an until-end-of-today grace window when yesterday qualifies;
- longest streak;
- дата начала текущей серии;
- нейтральное сообщение после перерыва без агрессивного loss framing.

Алгоритм учитывает:

- IANA timezone пользователя;
- смену месяца и года;
- високосный день;
- backdated записи;
- удаление и восстановление сессии;
- несколько книг в день как один qualifying day.

## 13. Годовые цели

MVP поддерживает одну цель по завершённым reading runs на календарный год.

- target: целое число 1–999;
- progress: количество `completed` runs с `finished_on` в выбранном году;
- настройка `include_rereads`, по умолчанию `true`;
- снижение цели разрешено и фиксируется без негативных сообщений;
- отсутствие цели не блокирует остальные функции.

Дополнительные цели по страницам и минутам — после MVP.

## 14. Серии и циклы

Серия принадлежит пользователю и добавляется вручную.

Поля:

- название;
- необязательное описание;
- автор/создатель;
- статус: planned, in_progress, completed, abandoned;
- обложка серии: выбранная книжная обложка или пользовательское изображение;
- записи книг с `sort_order` и отображаемым `position_label` (`0.5`, `1`, `2`, `companion`).

Функции:

- добавить уже имеющуюся книгу;
- создать placeholder будущей части;
- менять порядок drag-and-drop и доступной клавиатурной альтернативой;
- отмечать прочитанные части по завершённым runs;
- видеть `4 of 7` / `4 из 7`;
- быстро открыть следующую непрочитанную книгу.

Книга может входить более чем в одну пользовательскую коллекцию/серию, если пользователь этого хочет.

## 15. Завершение книги

При `Complete book` / `Завершить книгу` пользователь видит:

- дату завершения;
- оценку от 0.5 до 5 с шагом 0.5, необязательно;
- короткое впечатление, необязательно;
- `Favorite candidate` / `Кандидат в любимые`;
- `Disappointment candidate` / `Кандидат в разочарования`;
- подтверждение, что годовая цель обновилась.

Книга не обязана попадать ни в одну номинацию. Одновременно выбрать обе противоположные номинации нельзя.

## 16. Итоги месяца и года

### 16.1 Автоматические данные

- завершённые книги;
- уникальные книги;
- rereads;
- читающие дни;
- минуты и страницы, если они вводились;
- longest streak внутри периода;
- наиболее активная неделя;
- серии, в которых появился прогресс;
- мозаика обложек.

### 16.2 Пользовательский выбор

- favorite book;
- biggest disappointment;
- favorite cover;
- favorite series progress.

В трёх книжных категориях доступны все книги личной библиотеки независимо от статуса: прочитанные, читаемые, отложенные и не законченные. Выбор необязателен и может быть изменён позже. Годовой итог не открывается только в декабре: текущие итоги доступны всегда, а завершённая версия периода помечается как завершённая.

### 16.3 Sharing

В MVP recap можно просмотреть внутри приложения. Экспорт красивой share-card PNG рассматривается после стабильного beta-релиза.

## 17. Главная страница

Порядок блоков:

1. приветствие и дата;
2. current reading hero с быстрым check-in;
3. годовая цель;
4. current/longest streak;
5. компактная лента последних семи дней;
6. последние завершённые книги;
7. незавершённые серии;
8. ссылка на текущий monthly recap.

Если пользователь ничего не читает, главный CTA — `Choose your next book` / `Выбрать следующую книгу`, а не пустой дашборд.

## 18. Настройки и владение данными

- язык;
- timezone;
- light/dark/system theme;
- включение rereads в цель;

Удаление аккаунта удаляет связанные пользовательские строки и собственные загруженные файлы. Действие не должно выполняться одной случайной кнопкой.

## 20. Доступность

- WCAG 2.2 AA как целевой минимум;
- полноценная клавиатурная навигация;
- видимый focus ring;
- alt text для обложек: название + автор;
- декоративные изображения имеют пустой alt;
- управление не зависит только от цвета;
- `prefers-reduced-motion` отключает необязательную анимацию;
- touch target не меньше 44×44 px;
- интерфейс работает при 200% zoom;
- drag-and-drop всегда имеет кнопочную/клавиатурную альтернативу.

## 21. Безопасность и приватность

- RLS включён для каждой пользовательской таблицы и storage policy;
- `service_role` запрещён в браузере и `NEXT_PUBLIC_*`;
- server actions/routes повторно валидируют ownership;
- Zod используется на границе ввода;
- OAuth redirect allowlist ограничен известными URL;
- внешние book-search запросы проходят через контролируемый server endpoint;
- server endpoint имеет rate limit, timeout и нормализацию ответа;
- загрузки ограничены JPEG, PNG и WebP; SVG/GIF не принимаются;
- максимальный исходный файл обложки — 5 MB;
- имена файлов не используются как доверенный путь;
- логи не содержат токены, полные OAuth payload или приватные заметки;
- секреты хранятся только в локальном `.env.local` и настройках платформ;
- разные Supabase-проекты для development и production.

## 22. Производительность

- server components по умолчанию; client components только для интерактивности;
- изображения обложек получают корректные `sizes`, lazy loading и placeholder;
- библиотека загружается страницами;
- календарный запрос получает только нужный диапазон дат;
- recap-агрегации выполняются на сервере/SQL, а не загрузкой всей истории в браузер;
- внешние результаты поиска не сохраняются до выбора пользователем;
- optimistic UI допустим только с явным rollback при ошибке;
- Lighthouse mobile targets перед публичной beta: Performance ≥ 80, Accessibility ≥ 95, Best Practices ≥ 90, SEO публичных страниц ≥ 90.

## 23. Наблюдаемость

До public beta:

- structured server logs без чувствительных данных;
- отдельная обработка ожидаемых и неожиданных ошибок;
- user-facing error boundary;
- correlation/request ID для server operations;
- health check для критичных server routes;
- внешняя аналитика не добавляется без отдельного privacy-решения.

## 25. Обязательные тесты

### Unit

- streak для today/yesterday/gap;
- longest streak;
- переход через месяц, год и leap day;
- timezone boundary;
- годовая цель с rereads on/off;
- status transitions;
- page/percent/minute validation;
- pluralization RU/EN;
- cover fallback priority;
- series ordering.

### Database/RLS

- пользователь читает и изменяет только свои данные;
- нельзя подменить `user_id`;
- session нельзя связать с чужим reading run;
- series entry нельзя связать с чужой книгой;

- каскадное удаление аккаунта проверено;
- constraints отклоняют невозможные значения.
